### 2. Patches whose removal would drop a data-loss, credential-exposure, or silent-revert control

The clearest direct silent-revert control is **P09 (`8c44d1fb45`)**: dropping it allows an LLM specify operation to replace a frozen published ACCEPTANCE contract. **P04 (`acdbb56126`)** provides the same class of protection during decomposition and prevents zombie-card resurrection. **P01 (`37663d594a`)** prevents receipt/handoff data from being silently emptied before Gate 4. **P13 (`5674c5f82d`)** prevents fallback to bare-thread provider code that loses profile/secret context, with wrong-profile credential/memory exposure risk. P03 supplies freeze audit evidence and parser dependencies but its digest-verdict helper alone is not an active edit-prevention control. P06/P08 contain security or fail-closed logic, but it is dormant and therefore not live protection in this tree.

### 3. Patches with no upstream equivalent and no live failure they prevent

Yes: **P05, P06, P07, P08, P12 and P14** have no upstream implementation and prevent no failure on a reachable live path (P14 is meaningful only while P06 remains). **P02** likewise prevents no runtime failure and contributes no independent content beyond P01.
